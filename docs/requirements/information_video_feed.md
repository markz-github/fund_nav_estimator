# 信息流视频采集与汇总需求

## 目标

在 `information` 模块中维护信息源账号，定时扫描 B站账号发布的新视频，调用本地 Bilinote 生成文字版总结，并按汇总任务配置提交给本地 Hermes 生成二次汇总文档。

## 当前状态

- 状态：已完成第一版。
- 第一版实现 B站来源，架构预留其他视频平台扩展。
- 账号、接口参数、视频、Bilinote 总结、Hermes 汇总文档均可入库维护和查看。

## 需求清单

- 信息源维护：
  - 支持维护 B站 UID 或 space 主页 URL。
  - 信息源支持维护分类，默认 `财经`；现有信息源均归为财经分类。
  - 支持启用、停用、删除来源账号。
  - 后续新增视频平台时，应通过信息源适配器扩展。
- 视频扫描：
  - 定时扫描每 3 分钟执行一次，每次只扫描 1 个启用的信息源账号，按 `last_scanned_at` 最久未扫描优先轮询，降低被平台风控的概率。
  - 手动扫描也必须写入任务日志。
  - 前端手动扫描支持选择一个或多个信息源账号；未选择时扫描全部启用账号。
  - 第一版扫描规则：对每个启用来源请求 B站投稿列表第一页，按发布时间倒序获取最新视频；手动扫描默认获取最新 20 条，适配器限制每次 1 到 50 条。
  - B站图文投稿也应入库，内容类型标记为 `article`；图文投稿不进入 Bilinote 视频总结任务。
  - 支持在信息流设置页配置图文投稿过滤关键词；关键词可用换行、逗号或分号分隔，扫描时或提交 Hermes 图文笔记前若图文投稿标题或正文命中任一关键词，则在信息源列表中标记为“无效内容”，并跳过后续 Hermes 笔记生成。
  - 图文投稿入库后直接提交单条 Hermes 笔记任务，结果写入笔记管理，不进入笔记汇总；图文笔记使用独立提示词，不使用系统设置里的 Hermes 笔记汇总说明。
  - 第一版不按发布时间窗口过滤，因此不是“最近 N 小时/天”的增量扫描；是否入库由 `platform + external_video_id` 去重决定。
  - B站扫描支持在信息流设置页维护 Cookie；配置后请求 B站投稿列表接口时应放入 `Cookie` 请求头，不应在服务日志、任务日志或异常信息中打印 Cookie 明文。
  - 新视频按 `platform + external_video_id` 去重入库。
  - 扫描入库的视频默认继承所属信息源分类；现有视频均归为财经分类。
  - 扫描失败写入任务日志或数据异常。
  - 扫描过程应写入服务日志，包括扫描开始、来源数量、单来源请求、返回条数、新增条数、重复条数和失败原因。
- 笔记生成：
  - 根据视频链接调用本地 Bilinote。
  - 对视频投稿，Bilinote 负责生成笔记；对图文投稿，Hermes 负责生成笔记。两者在系统中都是 `information_video_notes`，通过 `provider` 区分。
  - 前端手动生成总结支持选择一个或多个视频；未选择时按默认规则处理待生成总结的视频。
  - 使用 `/api/generate_note` 创建任务，使用 `/api/task_status/{task_id}` 轮询结果。
  - Bilinote 同一时间只提交一个新任务；提交任务只负责调用 `/api/generate_note`、创建笔记记录并保存 Bilinote 返回的 `task_id`。
  - Bilinote 提交任务应支持在设置页配置视频时间窗口，只对最近 N 天内发布或入库的视频生成总结；默认 3 天，设置为 0 表示不限制。
  - Bilinote 结果由后续定时轮询任务调用 `/api/task_status/{task_id}` 获取，可能经过多轮轮询后才写入最终笔记正文。
  - Bilinote 任务状态检查间隔为 30 秒。
  - 运行超过 1 天仍未得到结果的 Bilinote 任务应标记为过期失败。
  - 支持在前端手动将选中的 Bilinote 视频总结任务置为失败状态。
  - 已手动置为失败的投稿记录不再继续轮询外部任务状态；轮询写回结果前应检查投稿记录状态，若已是失败则跳过，不覆盖失败状态和笔记内容。
  - 信息源列表中失败状态的投稿记录应提供重试按钮；重试将投稿恢复为“待生成笔记”，并复用同一条笔记记录，将笔记状态恢复为 `pending`、清空旧任务 ID、正文、错误和原始响应，后续按首次进入生成笔记流程继续提交和轮询。
  - 笔记管理中失败且保留外部任务 ID 的笔记应提供“重新轮询”操作；该操作不重新提交生成任务、不清空外部任务 ID，只将笔记和投稿恢复为运行中，后续轮询按原任务 ID 获取结果。
  - 提交 Bilinote 任务和轮询 Bilinote 结果应分别写入任务日志；提交任务日志应保存目标视频 ID 和 Bilinote 返回的 `task_id`，失败时必须在任务日志中记录清楚失败原因。
  - 笔记管理中的 `information_video_notes` 只保存同一视频、同一 provider 最后一次生成任务的结果，包括状态、正文、外部任务 ID、错误信息和原始响应；失败后重试不新增笔记记录，而是在原有失败记录上更新。
  - 所有历史生成任务、重试过程和失败原因由 `task_logs` 承载，前端运行状态页应能在任务日志列表中看到失败原因。
  - Bilinote 默认参数通过系统设置页维护，包括 `provider_id`、`model_name`、`quality` 和接口地址。
  - 总结结果、任务 ID、状态、错误信息和原始响应保存到数据库。
  - 笔记正文和外部接口原始响应字段使用 `LONGTEXT`；代码不截断正文或原始响应，写入失败时按任务失败记录日志和异常。
  - 从 Bilinote 原始响应提取 Markdown 正文时，应规范化行首有序列表标记，避免 `1\.` 这类转义符作为正文显示；前端 Markdown 渲染应支持有序列表展示。
  - 手动生成总结也必须写入任务日志。
- Hermes 二次汇总：
  - 汇总任务应按配置的 cron 表达式执行，按视频平台、信息分类和发布日期范围汇总已完成 Bilinote 总结。
  - 汇总任务配置项包括任务名称、信息分类、平台、启用状态、定时 cron、是否推送微信、汇总结果名称模板，以及“汇总发布范围从几天前到昨天”。
  - 汇总任务配置的 cron 表达式应兼容常规 cron 星期数字语义：`0` 或 `7` 表示周日，`1` 表示周一，依次到 `6` 表示周六；保存和注册定时任务时应转换为 APScheduler 可正确识别的星期表达。
  - 项目启动时应根据启用的汇总任务配置注册定时任务；汇总任务配置新增、修改、启停或删除后，应刷新已注册的定时任务。
  - 汇总说明归属汇总任务配置；任务未填写说明时使用默认汇总说明。
  - 定时汇总文档应保存来源汇总任务配置 ID；若汇总任务配置被软删除，笔记汇总列表仍应通过软删除记录展示任务名称。没有汇总任务配置 ID 的文档视为手动汇总。
  - 汇总结果名称模板使用 Python `str.format` 语法，支持 `{start_date:%Y-%m-%d}`、`{end_date:%Y-%m-%d}`、`{category}`、`{platform}` 等变量。
  - 默认配置包含财经昨日汇总（昨天，`0 7 * * *`）和财经近 7 天汇总（7 天前到昨天，`30 7 * * mon`），后续可在设置页新增其他分类、时间窗口或触发时间。
  - 支持在笔记管理列表多选已完成笔记，手动生成自定义 Hermes 汇总文档；自定义汇总不应影响配置汇总的去重和视频状态流转。
  - 手动汇总点击按钮后应弹窗确认，默认带入默认汇总说明，用户可在弹窗内临时修改汇总名称和汇总说明。
  - 调用本地 Hermes runs 能力，鉴权令牌、run 路径和轮询路径可配置。
  - Hermes 汇总生成采用异步任务模型：提交汇总时只调用 run 接口并保存 `run_id`，文档状态置为 `running`；后续由定时轮询任务调用状态接口，拿到正文后写入汇总文档。
  - 支持在设置页配置默认汇总说明；手动汇总默认使用默认说明，汇总任务未配置说明时也使用默认说明。
  - 支持在设置页配置微信推送接口地址和可选推送 Token。
  - 汇总任务配置应支持在设置页针对单个配置手动立即执行一次；立即执行复用该配置的范围、标题模板、汇总说明和微信推送规则，并写入任务日志。
  - 提交给 Hermes 的每条笔记上下文应包含来源作者、发布账号、视频标题、视频发布时间和视频链接，避免汇总时丢失观点来源和时间背景。
  - Hermes 汇总 prompt 应要求模型标注重点，突出核心结论、风险信号、分歧观点和行动建议。
  - 汇总文档正文、run ID、状态、错误信息和原始响应保存到数据库。
  - 笔记汇总页面是文档列表，不直接展示汇总正文；点击文档详情后展示正文。
  - 笔记汇总列表使用表格样式展示，默认按创建时间倒序排列。
  - 笔记汇总详情页应按 Markdown 渲染 Hermes 返回的文本正文；Hermes 返回值本身是字符串输出，不额外提供 Markdown 类型标记，因此前端按 Markdown 兼容渲染。
  - 笔记汇总详情页不提供刷新详情按钮。
  - 笔记汇总页面不提供刷新列表按钮；页面加载和生成/重试后自动刷新列表。
  - 笔记汇总页面对失败文档提供重试按钮；重试应复用原汇总文档和原始笔记范围。
  - 手动选择笔记生成自定义汇总时，用户可以填写汇总名称；名称非必填，空值时后端自动生成默认名称。
  - 汇总任务配置启用微信推送后，Hermes 汇总轮询完成并写入正文时立即调用微信推送接口发送该汇总。
- 前端页面：
  - 信息流功能访问路径使用 `/information/videos`。
  - 页面提供左侧全局菜单，可在基金估值、视频信息流、笔记管理、运行状态和设置之间切换。
  - 信息源管理使用独立页面 `/information/sources`。
  - 笔记汇总使用独立页面 `/information/summaries`，页面同时展示手动汇总和各汇总任务生成的结果，并展示汇总任务名称。
  - 笔记汇总页面支持按汇总任务筛选；筛选参数使用汇总任务配置 ID，并提供“手动汇总”选项用于筛选没有汇总任务配置 ID 的文档。
  - 提供信息源维护。
  - 信息源管理页新增和修改信息源均通过弹窗表单完成，列表中不直接编辑字段。
  - 信息源管理列表展示当前系统中每个账号的视频数量和笔记数量；视频数量可跳转到该账号的视频列表，笔记数量可跳转到该账号的笔记管理列表。
  - 信息源管理、信息管理、笔记管理和笔记汇总列表均支持分页；分页状态应在信息管理、笔记管理和笔记汇总页面的 URL 查询参数中保留，便于跳转和刷新。
  - 视频列表展示来源账号。
  - 视频列表展示视频投稿时长；图文投稿不展示时长或展示为 `-`。
  - 信息管理列表展示内容数据库 ID、内容类型和最新笔记数据库 ID，便于和任务日志对照排查。
  - 信息管理列表展示入库方式，并支持按扫描入库和手动添加筛选。
  - 信息流各列表页应支持带查询参数跳转并从 URL 初始化筛选条件，例如从信息源管理跳转到指定账号的视频列表、从笔记跳转到关联视频、从运行状态跳转到指定任务类型或目标视频。
  - 表格中可跳转字段应有明确视觉提示，例如使用不同颜色、加粗或下划线，避免与普通文本混淆。
  - 视频列表按发布时间倒序展示。
  - 视频列表支持按账号、处理状态和发布时间筛选，发布时间默认筛选近 3 天。
  - 提供独立接口设置页维护 B站 Cookie、Bilinote、Hermes、微信推送参数和 Bilinote 总结任务的视频时间窗口。
  - 接口设置页提供图文投稿过滤关键词配置，便于过滤无关图文内容。
  - 提供独立汇总设置页维护默认汇总说明和汇总任务配置；新增汇总任务通过弹窗添加，可新增、启停、删除汇总任务配置，并调整分类、汇总发布日期范围、定时 cron、是否推送微信、结果名称模板和任务级汇总说明。
  - 汇总设置页每个汇总任务配置应提供“立即执行”操作，用于不等待 cron 定时触发时手动提交一次该配置汇总。
  - 展示信息源列表、笔记生成状态和笔记汇总文档。
  - 提供笔记管理列表与笔记详情页，可查看笔记正文、错误信息、关联视频、视频时长和原始响应；图文投稿对应笔记不展示时长或展示为 `-`，笔记正文按 Markdown 格式渲染。
  - 笔记详情和汇总详情的 Markdown 渲染应兼容 `$$ ... $$` 数学块写法，避免将公式分隔符拆成普通段落显示。
  - 笔记详情接口默认不查询 `raw_response`；原始响应应通过按笔记 ID 查询的独立接口懒加载，前端 Raw Response 区域默认收起，展开时再请求并展示，并支持原文和 JSON 结构化展示切换。
  - 提供手动触发扫描和生成总结。

## 手动添加链接总结流程

- 目标：允许用户在不维护来源账号或未等到扫描任务的情况下，手动录入一个 B站视频或图文链接，并进入既有笔记生成、轮询、汇总流程。
- 后端能力：
  - 新增“手动添加链接”接口，只接收链接和分类；分类必填，支持使用已有分类或新增分类。
  - 后端应根据链接自动识别平台、内容类型、标题、来源账号、正文等信息；手动添加内容的发布时间统一使用添加时间。
  - 后端应尽量自动识别 B站视频链接和图文专栏/动态链接；识别失败时返回明确错误，不要求用户补充内容类型。
  - 对视频链接尽量解析 BVID；对图文链接尽量解析 article/dynamic 等平台内容 ID；无法解析时使用链接哈希生成稳定 external ID，仍按 `platform + external_video_id` 去重。
  - 手动内容应写入 `information_videos`：视频写 `content_type = video`、状态 `note_pending`；图文写 `content_type = article`、状态 `note_pending`，并在可获取时保存 `content_text`；`ingest_method` 写为 `manual`。
  - `source_id` 可指向一个“手动录入”虚拟信息源，或在模型允许后改为可空来源；虚拟信息源应按平台和分类复用，避免每条链接创建一个来源。
  - 视频内容沿用 Bilinote 提交与轮询；图文内容沿用 Hermes 单条图文笔记任务，不进入 Bilinote。
  - 手动添加只负责入库并进入待生成笔记状态；笔记生成时机和顺序沿用现有待处理内容流程，不提供“是否立即生成笔记”选项。
  - 手动添加和后续生成、轮询、失败重试都必须写入任务日志。
- 前端能力：
  - 信息管理页增加“添加链接”入口，使用弹窗表单录入链接和分类。
  - 分类字段必填，可从已有分类下拉选择，也可手动输入新分类；不默认填 `财经`。
  - 添加成功后跳转或筛选到该内容，用户可在信息管理页查看状态和失败原因，也可进入笔记管理查看笔记正文。
- 汇总衔接：
  - 手动添加的视频或图文与扫描内容一样进入匹配分类和时间范围的配置汇总；图文若只生成单条 Hermes 图文笔记且不进入笔记汇总，则应在页面上明确展示其不参与配置汇总。
  - 自定义手动汇总仍由用户选择笔记决定，不改变配置汇总去重规则。

## 验收标准

- 用户可以在前端添加 B站来源账号并手动触发扫描。
- 扫描到的新视频会入库，重复扫描不会重复入库。
- 配置 Bilinote 参数后，可以为待处理视频生成文字总结并保存。
- 配置汇总任务可以把匹配平台、分类和发布时间范围的已完成总结合并为一篇 Hermes 汇总文档。
- 定时任务可以按配置触发扫描、总结和汇总。
- 失败场景应有任务日志或异常记录，前端能看到失败状态。

## 待确认或待处理

- Hermes runs 接口的最终稳定路径、请求体和响应字段。
- B站公共接口的访问稳定性和必要的 cookie/风控处理。
- 其他视频平台来源适配器。
- 汇总规则的细化，例如按账号、主题、关键词或人工选择总结。
